# Чемпионат среди Артистов по футболу 2026-2027

Статический сайт футбольного чемпионата: турнирная таблица, команды с составами (и фото игроков),
расписание и результаты матчей, а также полноценная админ-панель для ведения турнира.

* **Без серверной части и базы данных** — это чистая статика (HTML + CSS + JS), поэтому её можно бесплатно
  разместить на GitHub Pages, Cloudflare Pages, Netlify или Vercel.
* **Общие данные для всех устройств** — результаты хранятся файлом `data.json` в этом же репозитории,
  поэтому их видят посетители с любых устройств, а администратор публикует изменения одной кнопкой.
* **Без внешних CDN** — Tailwind CSS собирается заранее в один файл, шрифт Roboto и иконки лежат в проекте.
  Сайт работает офлайн и не зависит от чужих серверов.

## Возможности

**Публичная часть**

| Страница | Что показывает |
|---|---|
| Главная | Счётчики турнира, последние результаты, ближайшие матчи |
| Таблица | Место, И/В/Н/П, мячи, разница мячей, очки; нажатие на команду открывает её страницу |
| Команды | Карточки команд с местом, очками, играми и составом (у игроков видны фото); поиск по названию, нажатие на команду открывает её страницу |
| Команда | Отдельная страница: место, очки, игры, ГЗ и ГП (забитые и пропущенные мячи), победы/ничьи/поражения, разница мячей, состав с фото и все матчи команды |
| Игрок | Карточка игрока: крупное фото, команда, дата рождения (и возраст), голы и карточки за турнир, а также «принадлежность» — свободный текст от администратора (школа, клуб, тренер) |
| Матчи | Все матчи с фильтрами «все / завершённые / предстоящие» и поиском по названию команды; нажатие на матч открывает детальный результат: счёт, составы, голы и карточки |
| Лучшие бомбардиры | Игрок, команда и забитые мячи; сортировка по голам (при равенстве — по имени), в таблицу попадают только забивавшие |

**Названия команд кликабельны везде:** в турнирной таблице, в карточках матчей (на главной, на странице
«Матчи» и на странице команды), в детальном результате матча и в списке бомбардиров — нажатие открывает
страницу команды (`#/team/3`). В админке название команды в карточке матча открывает её карточку
в разделе «Команды».

**Имена игроков тоже кликабельны везде**, где они видны: в составе команды (список «Команды» и страница
команды), в детальном результате матча и в таблице бомбардиров. Нажатие открывает **карточку игрока**
(`#/player/3/1` — команда и номер в заявке): крупное фото, команда, дата рождения, статистика игрока
и принадлежность. Ссылкой на карточку можно поделиться; кнопка «Назад» вернёт туда, откуда вы пришли.


**Кнопка «Назад»** видна вверху любой страницы, как только вы куда-то перешли: она возвращает именно
на предыдущую страницу (например, Таблица → команда → «Назад» вернёт в таблицу, а не в список команд),
и рядом подписано, куда вернётесь. Переходы внутри раздела (список ⇄ детальный результат матча,
список ⇄ страница команды) новой страницей не считаются.

**Админ-панель** (вход по паролю)

В шапке панели — горизонтальное меню из двух кнопок-разделов, чтобы ничего не искать:

| Раздел | Что внутри |
|---|---|
| **Команды** | список команд (клик по названию открывает состав), добавление команды, переименование и удаление команды в её карточке, загрузка **эмблемы команды**, работа с игроками: добавление, переименование, удаление, **загрузка фото** и **данные игрока** — дата рождения и принадлежность |
| **Матчи** | список матчей (сначала прошедшие, затем предстоящие) с поиском по названию команды, добавление и правка матча, а по клику на матч — карточка со счётом, голами, жёлтыми и красными карточками |

Раздел «Команды» открывается сразу после входа; разделы переключаются кнопками (и стрелками ←/→
с клавиатуры). Общая сводка турнира и блок «Настройки» видны в любом разделе.

**Карточка матча.** Вверху названия команд и счёт («Добрик 1 : Оля 2») с кнопкой «Сохранить счёт»,
ниже — составы обеих команд. У каждого игрока три отметки: **мяч** — гол, **жёлтый прямоугольник** —
жёлтая карточка, **красный прямоугольник** — красная карточка. Нажатие записывает событие, иконка
подсвечивается своим цветом и показывает количество (дубль, вторая карточка), а кнопка «Убрать»
снимает последнюю запись игрока — её можно нажать несколько раз подряд, пока не уберёте лишнее.
Рядом со счётом видна подсказка «Записано голов: 2 из 3», а в списке матчей — число записанных
голов и карточек.

**Детальный результат матча.** На странице «Матчи» любой посетитель может нажать на матч и посмотреть
подробности: счёт, составы обеих команд (с фото игроков), кто забил и кто получил карточки. У матча есть
собственный адрес — `#/match/5`, поэтому ссылкой на конкретный матч можно поделиться, а кнопка «назад»
возвращает к списку матчей.

## Фото игроков и эмблемы команд

Фото живут **файлами в этом же репозитории** (папка `assets/photos/`), а в `data.json` хранится только
путь к файлу — вида `assets/photos/ivanov-a-8f3c21.jpg` (фото игрока) или
`assets/photos/team-spartak-4d5e6f.jpg` (эмблема команды). Так документ остаётся маленьким (важно для
localStorage), картинки раздаёт сам сайт, а история загрузок навсегда остаётся в коммитах.

### Подготовка (один раз)

1. Откройте сайт → **Админ** → пароль.
2. Кнопка **«Настройки»** в шапке панели → вставьте токен GitHub → **«Сохранить токен»**.
   Без токена фото загрузить нельзя: файл нужно записать в репозиторий, а это делает только токен
   (права `Contents: Read and write`, см. раздел «Как создать токен»).

### Как добавить фото игроку

1. Админка → раздел **«Команды»** → нажмите название нужной команды (откроется её карточка с составом).
2. В строке игрока нажмите кнопку **с фотоаппаратом** (подсказка «Загрузить фото»).
3. Выберите файл (JPEG, PNG или WebP) с телефона или компьютера.
4. Появится надпись «Загружаю…», затем:
   * фото **сразу** появится в составе (предпросмотр из памяти) — ждать публикации не нужно;
   * в репозиторий уйдёт отдельный коммит «Фото игрока «Иванов А.» (Спартак) — файл сайта»;
   * путь попадёт в `data.json` и опубликуется обычной авто-публикацией (кнопка «Опубликовать сейчас»
     тоже подойдёт).
5. У посетителей фото появится через ~30–60 секунд — как и любые другие изменения. Сайт отдаёт новый
   файл чуть позже, чем сами данные (публикация на GitHub Pages занимает около минуты), поэтому страница
   **сама повторяет загрузку картинки** (см. «Если фото не появилось на другом устройстве» ниже) —
   перезагружать вкладку не нужно.
6. Повторная загрузка **заменяет** фото (имя файла то же). Кнопка **«Убрать фото»** (перечёркнутый
   фотоаппарат) снимает фото с игрока.

### Как добавить эмблему (фото) команды

1. Админка → раздел **«Команды»** → нажмите название команды.
2. В карточке команды, сразу под кнопками «Переименовать» / «Удалить команду», есть **эмблема** и кнопка
   **«Загрузить эмблему»** — она относится ко всей команде, а не к игроку.
3. Выберите картинку: подойдёт и логотип, и общее фото команды. Дальше всё так же, как с фото игрока:
   сжатие в браузере, коммит «Эмблема команды «Спартак» — файл сайта», путь в `data.json`.
4. Кнопка **«Убрать фото»** рядом убирает эмблему (файл остаётся в истории репозитория).

**Где видна эмблема:** в турнирной таблице, в списке команд (карточка команды), в её заголовке на
странице команды, в карточках матчей, в детальном результате матча и в «Лучших бомбардирах» —
везде вместо бейджа с инициалами. Если эмблемы нет, показывается прежний бейдж, вёрстка не меняется.

### Как фото попадают в репозиторий

Браузер сам готовит картинку: квадрат по центру, `512×512`, JPEG — обычно получается 20–80 КБ.
Настройки — в `assets/js/config.js` (`window.FT_CONFIG.photo`): `folder`, `maxSize`, `quality`,
`maxSourceBytes`, `maxResultBytes`, `retryDelays`.

### Если фото не появилось на другом устройстве

Данные (`data.json`) посетители читают напрямую из репозитория и видят их через секунды, а **картинки
раздаёт сайт** — GitHub Pages публикует новый файл примерно через минуту. Плюс ответ «файла нет» (404)
браузер запоминает на 10 минут: без дополнительных шагов устройство, открывшее страницу в эту минуту,
показало бы «сломанную» картинку ещё долго после публикации.

Поэтому приложение:
* увидев, что фото не загрузилось, **само повторяет запрос** — три раза (через 4, 15 и 45 секунд) со
  сбросом кэша (`?t=…`), так что фото появляется само, без перезагрузки страницы;
* если файла всё ещё нет (например, его убрали из репозитория), вместо сломанной картинки показывает
  прежний бейдж с инициалами — вёрстка не ломается.

Паузы настраиваются в `assets/js/config.js` — `window.FT_CONFIG.photo.retryDelays`.

### Карточка игрока: дата рождения и принадлежность

Каждый игрок открывается нажатием на своё имя (состав команды, составы в матче, бомбардиры) — на странице
`#/player/<команда>/<номер>` видны крупное фото, команда, дата рождения с возрастом, голы и карточки
за турнир, а также **принадлежность** — свободный текст администратора.

Заполняется в админке:

1. Админка → раздел **«Команды»** → нажмите название команды.
2. В строке игрока нажмите кнопку **с буквой «i»** («Заполнить дату рождения и принадлежность»).
3. В открывшейся форме:
   * **Дата рождения** — календарь (будущие даты выбрать нельзя, как и годы до 1900);
   * **Принадлежность** — обычный текст: школа, клуб, тренер, с какого года играет. Ограничение —
     **200 символов** (примерно 3–4 коротких предложения), рядом виден счётчик набранных символов;
     переносы строк сохраняются, поэтому текст можно писать абзацами.
4. **«Сохранить данные»** — данные попадают в `data.json` (карта `playerInfo`) и уезжают на все устройства
   обычной публикацией. Кнопка **«Убрать данные»** очищает дату рождения и принадлежность.

Если администратор вошёл в панель, на самой карточке игрока есть кнопка **«Заполнить данные игрока»** —
она открывает админку сразу с формой этого игрока. Пустые поля показываются посетителям как
«не указана», поэтому карточку можно заполнять постепенно.

**Что важно помнить**

* Фото **публичны** и остаются в истории git даже после удаления — стоит взять согласие у игроков.
* Репозиторий растёт навсегда: 100 игроков по ~60 КБ — это около 6 МБ, нормально. Именно поэтому фото
  сжимается в браузере: загружать в репозиторий файлы по 3–5 МБ нельзя.
* Git LFS не используется: GitHub Pages не отдаёт LFS-файлы, поэтому фото — обычные файлы репозитория.
* Токену нужны те же права, что и раньше (`Contents: Read and write`) — отдельных разрешений не требуется.
* Если фото не загрузилось (например, нет токена), данные не портятся: показывается понятная ошибка, а
  файл при желании можно положить в `assets/photos/` вручную и привязать повторной загрузкой.

* Публикация: токен GitHub, кнопки «Опубликовать сейчас», «Проверить доступ» и «Забрать из репозитория»,
  авто-публикация после изменений, ссылка на созданный коммит.
* Данные: возврат к демонстрационным данным (резервные копии — история коммитов в репозитории).

**Технические особенности**

* Роутинг на хэш-адресах (`#/standings`, `#/teams`, `#/match/5`, `#/team/3`, `#/player/3/1`): прямые ссылки и кнопка «назад» работают,
  это важно для статического хостинга.
* Строгая Content Security Policy, нет inline-скриптов и inline-стилей.
* Весь пользовательский ввод экранируется — имена команд и игроков не могут сломать разметку или внедрить скрипт.
* Повреждённые данные в localStorage не «роняют» сайт: данные нормализуются, показывается предупреждение.
* Доступность: `aria`-атрибуты, подписи полей, ссылка «Перейти к содержимому», ошибки через `role="alert"`.
* Адаптивность под телефоны: горизонтальной прокрутки нет ни на одной странице. Турнирная таблица
  показывается компактно (место, команда, игры, разница мячей, очки), остальные показатели — строкой
  под названием команды, кнопка «Все столбцы» раскрывает полный набор; кнопки разделов админки
  занимают всю ширину экрана, отметки голов и карточек — 40×40 (удобно нажимать пальцем),
  а строки списков админки превращаются в крупные кликабельные кнопки.

## Структура проекта

```
Футбольный турнир/
├── index.html                 # разметка всех страниц + SVG-спрайт иконок
├── data.json                  # ОБЩИЕ ДАННЫЕ ТУРНИРА (файл читают все устройства)
├── 404.html                   # страница «не найдено» (GitHub Pages, Netlify, Cloudflare)
├── robots.txt                 # правила для поисковых роботов
├── .nojekyll                  # для GitHub Pages: не обрабатывать сайт через Jekyll
├── _headers                   # заголовки безопасности и кэша (Netlify, Cloudflare Pages)
├── netlify.toml               # настройки Netlify (сборка не требуется)
├── assets/
│   ├── css/tailwind.css       # собранный CSS (коммитится в репозиторий)
│   ├── fonts/                 # Roboto (woff2, подмножества cyrillic + latin)
│   ├── js/config.js           # настройки: адрес репозитория, интервалы обновления, параметры фото
│   ├── js/logic.js            # чистая логика: расчёты, валидация, работа с хранилищем
│   ├── js/sync.js             # синхронизация с репозиторием: чтение, публикация, загрузка файлов
│   ├── js/photo.js            # подготовка фото игрока в браузере: квадрат, JPEG, имя файла
│   ├── js/app.js              # DOM: роутинг, отрисовка страниц, админ-панель
│   ├── photos/                # фото игроков (загружаются из админки, лежат файлами в репозитории)
│   ├── favicon.svg / .ico     # иконки сайта
│   ├── apple-touch-icon.png
│   └── og-image.svg / .png    # картинка для предпросмотра в соцсетях
├── src/input.css              # ИСХОДНИК стилей (собирается в assets/css/tailwind.css)
├── tailwind.config.js         # конфигурация Tailwind
├── tools/serve.js             # локальный сервер для просмотра и тестов
└── tests/                     # автотесты: логика, синхронизация, DOM (jsdom), браузер (puppeteer)
    └── helpers/mock-github.js # макет GitHub API для тестов (реальный GitHub не затрагивается)
```

## Локальный запуск

Можно просто открыть `index.html` в браузере, но правильнее поднять локальный сервер:

```bash
# вариант без Node.js
python3 -m http.server 8080

# вариант с Node.js (без зависимостей)
npm run serve          # http://127.0.0.1:8080
```

## Разработка и проверка

```bash
npm ci                 # dev-зависимости: tailwindcss, jsdom, puppeteer-core
npm run build:css      # пересобрать assets/css/tailwind.css после правок классов
npm run watch:css      # то же в режиме наблюдения
npm test               # 115 тестов: логика, фото, синхронизация, интерфейс (jsdom)
npm run test:browser   # 13 e2e-тестов в настоящем Chrome (включая публикацию и загрузку фото)
```

Chrome для браузерных тестов ищется в `CHROME_PATH`, кэше puppeteer или системных путях.
Если браузера нет — эти тесты просто помечаются пропущенными.

## Пароль администратора

* Пароль по умолчанию — **`admin`**; он задан в `assets/js/logic.js` в объекте `CONFIG` (`adminPassword`).
  Перед публикацией смените его на свой.
* Вход действует до закрытия вкладки (sessionStorage), кнопка «Выйти» завершает сессию.

> **Честное предупреждение о безопасности.** Это статический сайт без сервера, поэтому пароль хранится
> в исходном коде страницы: он закрывает панель от случайных посетителей, но не защищает данные от того,
> кто умеет открыть исходники. Настоящей авторизации на статике не бывает — если нужна реальная защита,
> понадобится серверная часть или готовый сервис с базой данных (Supabase, Firebase и подобные).

## Общие данные: как результаты попадают на все устройства

Сайт статический, поэтому «сервера» у него нет. Общие данные лежат файлом **`data.json` в этом же
репозитории на GitHub**, а сайт их читает и записывает так:

```
посетитель с любого устройства ──► читает data.json (без ключей, публично)
администратор в панели ─────────► пишет data.json через GitHub API (по токену, только у вас)
                                          │
                                          ▼
                              обычный коммит в репозитории:
                              история изменений и откат доступны на GitHub
```

* **Чтение** — сначала напрямую из репозитория (`raw.githubusercontent.com`, обновляется через несколько
  секунд после публикации), при сбое — файл с самого сайта, а без интернета — сохранённая копия в браузере.
  Ключи для чтения не нужны: данные турнира и так публичные.
* **Запись** — через GitHub API по токену. Токен **не хранится в коде сайта и в репозитории**: вы вводите
  его один раз в админке, и он остаётся только в браузере вашего устройства.
* У зрителей данные обновляются сами: раз в 5 минут при открытой вкладке и по кнопке «Обновить данные»
  в подвале сайта.

### Что делает администратор

1. Один раз: вводит токен в блоке **«Публикация результатов для всех устройств»** и нажимает «Сохранить токен».
2. Ведёт турнир как обычно: команды, матчи, счёт, игроки.
3. Изменения публикуются сами (галочка «Публиковать автоматически» включена по умолчанию) либо по кнопке
   **«Опубликовать сейчас»**. Статус виден рядом: «Опубликовано: 15 сентября 2026, 10:35» и ссылка на коммит.
4. Если нужно забрать свежую версию из репозитория (например, правили историю на GitHub) — кнопка
   **«Забрать из репозитория»**.

### Как создать токен (один раз, 5 минут)

1. Откройте <https://github.com/settings/personal-access-tokens/new> (Fine-grained token).
2. **Token name** — например, `football-tournament`.
3. **Expiration** — любой срок (например, 90 дней). По истечении создадите новый и введёте его в админке.
4. **Repository access** → `Only select repositories` → выберите репозиторий с сайтом.
5. **Repository permissions** → `Contents` → `Read and write`. Больше никаких прав не нужно.
6. **Generate token**, скопируйте значение (вида `github_pat_…`) и вставьте его в админке → «Сохранить токен».

Токен даёт доступ только к этому репозиторию и только к содержимому файлов. Если он утечёт,
зайдите на <https://github.com/settings/tokens> и отзовите его — данные турнира при этом не пострадают.

### Защита от потери результатов

* Повторное нажатие «Опубликовать», когда данные уже совпадают с репозиторием, не считается ошибкой:
  сайт просто сообщает, что публиковать нечего, и не создаёт лишний коммит.
* Перед публикацией сайт сверяет версии: если в репозитории данные **новее** ваших (например, кто-то
  опубликовал с другого устройства, а на этом осталась старая копия), публикация остановится
  с подсказкой «Забрать из репозитория» — затирания не будет.
* Кнопка «Забрать из репозитория» спрашивает подтверждение, если на устройстве есть данные,
  которых нет в репозитории, и **сохраняет копию**. Вернуть её можно кнопкой **«Восстановить копию»**
  (кнопка появляется, когда копия есть).
* Пустой турнир (например, все команды удалены) — это нормальное состояние: сайт покажет его как есть,
  без подстановки демонстрационных команд.
* GitHub дополнительно вернёт ошибку конфликта, если файл изменился между чтением и записью.
* Каждое изменение — отдельный коммит, поэтому любую версию можно вернуть на GitHub
  (страница коммита → «Revert»). Это история турнира: видно, что и когда менялось.
* Резервная копия — вся история коммитов в репозитории: любую версию `data.json` можно посмотреть
  и вернуть прямо на GitHub (страница коммита → «Revert»).

### Если нужно поменять репозиторий или ветку

Все настройки — в `assets/js/config.js`:

```js
window.FT_CONFIG.github = {
    owner: 'ЛОГИН',                 // владелец репозитория (аккаунт GitHub)
    repo: 'Football-turnament',     // имя репозитория
    branch: 'main',                 // ветка
    path: 'data.json'               // файл с данными
};
```

Там же настраиваются интервалы: `refreshIntervalMs` (как часто зрители подтягивают обновления,
`0` — выключить) и `autoPublishDelayMs` (пауза перед авто-публикацией, чтобы несколько быстрых правок
склеивались в один коммит).

## Как вести турнир

1. Откройте сайт → **Админ** → введите пароль. Откроется раздел **«Команды»** (кнопки разделов —
   в шапке панели, рядом с «Настройками»).
2. В разделе «Команды» виден список команд и форма **«Добавить команду»** под ним —
   пустые названия и дубликаты не принимаются.
3. Нажмите название команды — откроется её карточка: **эмблема команды** с кнопкой **«Загрузить эмблему»**,
   **состав**, кнопка **«Добавить игрока»**, переименование и удаление игроков, загрузка **фото игрока**
   (кнопка с фотоаппаратом: фото сжимается в браузере и уходит файлом в репозиторий), а также
   **данные игрока** — кнопка с буквой «i» открывает форму с датой рождения и принадлежностью,
   а также **«Переименовать»** и **«Удалить команду»**.
   Кнопка **«Все команды»** возвращает к списку. Удаление команды удаляет и её матчи.
4. Переключитесь на раздел **«Матчи»**: список идёт в порядке «сначала прошедшие, затем предстоящие»,
   над списком — строка **поиска**: введите часть названия команды, и останутся только её матчи
   (поиск складывается с фильтром «завершённые / предстоящие»),
   под списком — форма **«Добавить матч»** (команды, дата и, при желании, счёт; без счёта матч станет
   «предстоящим»).
5. Нажмите строку матча — откроется **карточка матча**: названия команд и счёт
   («Добрик 1 : Оля 2»), кнопка **«Сохранить счёт»**, а ниже — составы обеих команд.
   У каждого игрока три отметки: **мяч** — гол, **жёлтый прямоугольник** — жёлтая карточка,
   **красный прямоугольник** — красная карточка. Нажатие записывает событие (иконка подсвечивается
   и показывает количество — можно отметить дубль или вторую карточку), а кнопка **«Убрать»**
   снимает последнюю запись игрока: если отметили не того игрока или не ту карточку, нажмите её —
   и запись исчезнет (кнопку можно нажимать несколько раз подряд). Подсказка рядом со счётом
   показывает, сколько голов уже записано («Записано голов: 2 из 3»).
6. Отмеченные голы сразу попадают на публичную страницу **«Лучшие бомбардиры»**:
   имя игрока, команда и забитые мячи; сортировка — по голам (при равенстве — по имени),
   в таблицу попадают только те, кто забивал. Карточки игроков в этой таблице не показываются —
   они видны в карточке матча и в детальном результате.
7. В карточке матча доступны **«Переоткрыть матч»** (убрать результат из зачёта),
   **«Изменить команды и дату»** (форма заполняется, карточка закрывается) и **«Удалить матч»**.
   Кнопка **«Все матчи»** возвращает к списку.
8. Кнопка **«Демо-данные»** возвращает демонстрационный набор (например, чтобы начать заново).
   Отдельных кнопок экспорта/импорта файлов больше нет: резервная копия — это история коммитов
   репозитория, а копия данных перед заменой сохраняется автоматически (кнопка «Восстановить копию»).

Изменения публикуются в `data.json` этого репозитория (см. раздел «Общие данные» выше), поэтому результаты
видят посетители на любых устройствах. Если публикация не настроена (токен не задан), сайт продолжит
работать, но данные будут видны только на вашем устройстве.

## Бесплатная публикация

Проект уже подготовлен к бесплатному хостингу: это только статические файлы, без сборки на сервере,
без базы данных и без внешних CDN. Достаточно залить содержимое папки в репозиторий или в панель хостинга.

### Вариант 1. GitHub Pages (бесплатный домен вида `https://логин.github.io/репозиторий/`)

```bash
git init
git add .
git commit -m "Сайт футбольного турнира"
git branch -M main
git remote add origin https://github.com/ЛОГИН/РЕПОЗИТОРИЙ.git
git push -u origin main
```

Затем в репозитории: **Settings → Pages → Source: Deploy from a branch → Branch: `main`, папка `/ (root)` → Save**.
Через минуту сайт будет доступен по адресу `https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/` — это и есть бесплатный домен.
Файл `.nojekyll` уже добавлен, поэтому GitHub не будет пропускать папки и файлы с подчёркиванием (`_headers`).

### Вариант 2. Cloudflare Pages (бесплатный домен `*.pages.dev`)

**Create application → Pages → Connect to Git** → выберите репозиторий → Framework preset: `None`,
Build command: оставить пустым, Build output directory: `/` → Deploy.
Можно и без Git: **Direct Upload** и перетащить папку проекта.

### Вариант 3. Netlify (бесплатный домен `*.netlify.app`)

**Add new site → Import an existing project** (или просто перетащить папку в панель).
Публикуемый каталог — корень проекта, это уже прописано в `netlify.toml`. Команда сборки не нужна.

### Вариант 4. Vercel (бесплатный домен `*.vercel.app`)

**Add New → Project → Import** → Framework Preset: `Other`, Build Command: пусто, Output Directory: `./`.

### Чему соответствует проект (требования бесплатных хостингов)

| Требование | Как выполнено |
|---|---|
| `index.html` в корне | ✔ файл лежит в корне репозитория |
| Только статика, без Node.js и серверного кода | ✔ нужны лишь файлы; `npm` используется только для разработки |
| Относительные пути (сайт в подпапке) | ✔ все ссылки вида `assets/...`, роутинг на хэшах |
| HTTPS | ✔ даётся хостингом автоматически |
| Отсутствие внешних CDN | ✔ Tailwind собран в файл, шрифты и иконки локальные |
| Страница 404 и `robots.txt` | ✔ `404.html` и `robots.txt` в корне |
| Заголовки безопасности | ✔ в `_headers` (Netlify/Cloudflare) и CSP в `index.html` |
| Размер | ✔ около 720 КБ вместе со шрифтами и картинками |

### Что публикуется

GitHub Pages раздаёт весь репозиторий, поэтому вместе с сайтом будут доступны и служебные каталоги
(`tests/`, `tools/`, `src/`, `package.json`) — это обычные текстовые файлы, секретов в них нет, а `robots.txt`
просит поисковые системы их не индексировать. Если хочется публиковать только сам сайт, перенесите
`index.html`, `404.html`, `robots.txt`, `.nojekyll` и папку `assets/` в каталог `docs/` и укажите его
в настройках Pages (Branch: `main`, папка `/docs`). Netlify и Cloudflare Pages при прямой загрузке
получают только те файлы, которые вы загрузили.

### Бесплатный домен
* Все перечисленные хостинги сразу дают адрес третьего уровня: `*.github.io`, `*.pages.dev`, `*.netlify.app`, `*.vercel.app`.
* Красивый бесплатный поддомен можно получить на сервисах вроде `is-a.dev`, `js.org`, `eu.org` — они бесплатно
  выдают зону, а в DNS указывается адрес вашего хостинга.
* Домен второго уровня (`mysite.ru`) бесплатным не бывает: его нужно зарегистрировать, но подключить к
  любому из хостингов выше можно без доплат (SSL-сертификат выдаётся автоматически).

### Перенос сайта на другой аккаунт GitHub (смена бесплатного домена)

Адрес бесплатного домена GitHub Pages складывается из логина и имени репозитория:
`https://ЛОГИН.github.io/РЕПОЗИТОРИЙ/`. Чтобы он стал другим, есть три пути.

1. **Переименовать текущий аккаунт** — GitHub → *Settings → Account → Change username*.
   Репозитории и настройки переезжают автоматически, адрес сайта сразу становится
   `https://НОВЫЙ-ЛОГИН.github.io/Football-turnament/`. Минус: старое имя освобождается (его сможет
   занять кто угодно), и надёжного перенаправления со старого `*.github.io` нет.
2. **Создать новый аккаунт и перенести репозиторий** — на старом аккаунте
   *Settings → General → Transfer ownership*, новый аккаунт принимает приглашение.
   Можно и без передачи: создать на новом аккаунте пустой репозиторий и отправить туда полную копию:

   ```bash
   git clone --mirror https://github.com/СТАРЫЙ-ЛОГИН/Football-turnament.git
   cd Football-turnament.git
   git push --mirror https://github.com/НОВЫЙ-ЛОГИН/Football-turnament.git
   ```

   Затем в новом репозитории: **Settings → Pages → Deploy from a branch → `main` / `/ (root)`**.
   Если назвать репозиторий `НОВЫЙ-ЛОГИН.github.io`, сайт получит адрес без папки репозитория —
   `https://НОВЫЙ-ЛОГИН.github.io/`: код это поддерживает, все пути внутри сайта относительные.
3. **Оставить аккаунт и подключить свой домен** — *Pages → Custom domain*: адрес аккаунта из ссылки
   исчезнет совсем (бесплатный поддомен можно получить на `eu.org`, `is-a.dev` и подобных сервисах).

Что нужно поправить в проекте после переезда:

* `assets/js/config.js` → `owner` (и `repo`, если репозиторий переименован). Это **единственное** место,
  где указан аккаунт: внутри сайта все пути относительные, а CSP разрешает `api.github.com`
  и `raw.githubusercontent.com` независимо от владельца. Строки `AndreyMinenkov` в `tests/sync.test.js` —
  это просто пример данных для проверки сборки адресов, менять их не обязательно.
* Выпустить новый токен (Fine-grained, право `Contents: Read and write` на новый репозиторий)
  и ввести его в админке: «Настройки» → «Сохранить токен». Токен старого аккаунта не подойдёт.
* `data.json` переезжает вместе с репозиторием — результаты турнира сохранятся, публикация продолжит
  работать по тем же кнопкам.
* Локальная папка проекта на компьютере: `git remote set-url origin https://github.com/НОВЫЙ-ЛОГИН/Football-turnament.git`.
* Чтобы старые ссылки продолжали открываться, на старом аккаунте можно оставить в репозитории
  только `index.html` с перенаправлением:

  ```html
  <meta http-equiv="refresh" content="0; url=https://НОВЫЙ-ЛОГИН.github.io/Football-turnament/">
  ```

### Перед публикацией

1. Смените пароль администратора в `assets/js/logic.js` (`CONFIG.adminPassword`).
2. Если у сайта будет свой домен, укажите его в `<link rel="canonical">` и замените относительный путь
   в `og:image` на абсолютный (`https://ваш-домен/assets/og-image.png`) — так предпросмотр в мессенджерах
   и соцсетях будет работать надёжнее.
3. После правок стилей выполните `npm run build:css` и закоммитьте обновлённый `assets/css/tailwind.css`.
4. Прогоните проверки: `npm test` и `npm run test:browser`.

## Ограничения

* Общие данные лежат в файле `data.json` репозитория (публично). Локальная копия в браузере нужна для
  офлайн-работы и ускоряет загрузку; лимит localStorage около 5 МБ — это десятки команд и сотни матчей.
* Публикация с токеном занимает один коммит на изменение. Если хочется меньше коммитов, увеличьте
  `autoPublishDelayMs` в `assets/js/config.js`: несколько быстрых правок склеятся в один коммит.
* Пароль администратора хранится в коде страницы: это защита от случайных посетителей, а не от
  целенаправленного взлома (см. предупреждение выше). Токен публикации, в отличие от пароля, в коде
  не хранится — он живёт только в браузере администратора.
* Турнирная таблица считается по схеме «3 очка за победу, 1 за ничью»; при равенстве очков сравниваются
  разница мячей, забитые мячи и название команды.
