# Безопасность и персональные данные

Сайт полностью статический: нет серверного кода, базы данных, cookie, аналитики и внешних сервисов.
Все данные турнира — обычный файл `data.json` в публичном репозитории, который читают браузеры зрителей.
Отсюда главное правило: **то, что попало в `data.json`, в фото или в коммит, видят все и навсегда**.
Ниже — что именно публично, что уже сделано для защиты и что стоит сделать владельцу турнира.

## Что видят все посетители

| Что | Где лежит | Кто видит |
|---|---|---|
| Турнир: команды, составы, матчи, счёт, голы, карточки, дисквалификации | `data.json` | все, включая поисковые системы |
| Карточки игроков: игровой номер и принадлежность | `data.json` | все |
| Настройки турнира: правила дисквалификаций и выбранное оформление сайта | `data.json` (`settings`) | все |
| Фото игроков, эмблемы и галереи команд | `assets/photos/` | все по прямой ссылке |
| История изменений, включая удалённые данные | история git | все |
| Служебные файлы сайта | `README.md`, `SECURITY.md`, `tests/`, `tools/`, `src/`, `package.json` | все — GitHub Pages раздаёт репозиторий целиком |

Публично **не** доступны: пароль администратора панели (формально он лежит в коде, но защитой не является —
см. ниже), токен публикации (он живёт только в браузере администратора) и локальная копия данных в браузере.

## Персональные данные

* ФИО и фотография человека — это персональные данные: для публикации нужно согласие
  (152-ФЗ в России, GDPR в ЕС). Согласие храните у себя, а не в репозитории.
* Даты рождения с сайта убраны полностью (версия данных 11): карточка игрока хранит только игровой номер
  и принадлежность, а прежнее поле `birthDate` отбрасывается при загрузке данных. Так публикуется меньше
  персональных данных.
* Необязательное поле «принадлежность» (школа, клуб, тренер) можно не заполнять — сайт покажет «не указана».
* **Удаление в панели не удаляет данные из истории.** Удалённый игрок, фото или матч остаются в старых
  коммитах и доступны по прямой ссылке. Если человек требует убрать свои данные насовсем, нужна перезапись
  истории (`git filter-repo` или BFG) и `git push --force`. Учтите: GitHub может хранить старые объекты
  ещё некоторое время, а копии у тех, кто успел склонировать репозиторий, останутся. Самый надёжный путь —
  новый репозиторий без старых данных.
* Фотографии команд публикуйте без посторонних людей в кадре; чужие картинки из интернета не загружайте
  (авторские права).
* В подвале сайта указано, что фото и имена публикуются с согласия участников. Это напоминание для
  посетителей и для организатора: сами согласия хранятся у вас (бумага или закрытая папка), а не
  в репозитории и не на сайте.

## Пароль администратора

* Пароль задан в `assets/js/logic.js` (`CONFIG.adminPassword`) и потому известен любому, кто откроет
  исходники страницы. Это закрытая дверь от случайных посетителей, а не защита.
* Настоящая защита данных — GitHub-токен: без него записать что-либо в репозиторий невозможно.
* Поэтому меняйте пароль на значение, которое не используется нигде больше, и не считайте панель тайной:
  не вносите в неё то, что не должно попасть в публичный файл.

## Токен публикации

* Хранится только в браузере администратора (`localStorage`, ключ `ft.githubToken`) и уходит только на
  `api.github.com` заголовком `Authorization` — не в адресе запроса, поэтому не попадает в логи, историю
  git и заголовок `Referer`.
* Выдавайте токен с минимальными правами: Fine-grained, **один** этот репозиторий,
  `Contents: Read and write` и обязательно ограниченный срок. Больше никаких прав не требуется.
* Включите двухэтапную проверку GitHub; не вводите токен на сторонних сайтах; не пересылайте его
  в мессенджерах и не показывайте на скриншотах.
* Проверить и отозвать: <https://github.com/settings/tokens>. Отзыв не требует правок сайта — выпустите
  новый токен и введите его в панели: «Настройки» → «Сохранить токен».
* **Если токен попал в чужие руки:** отзовите старый, выпустите новый и проверьте данные — `git log -p`
  по файлу `data.json` и кнопка «Забрать из репозитория» в панели. Испорченную версию можно вернуть
  из истории коммитов: она и есть резервная копия (см. «Защита от потери результатов» в README).

## Что нельзя коммитить

Токены, пароли, ключи, файлы `.env`, личные телефоны и адреса, чужие персональные данные без согласия.
Перед коммитом смотрите, что именно уходит: `git status` и `git diff --cached`. Файл `.gitignore` уже
закрывает `node_modules/`, `.env*`, `*.pem`, `*.key`, резервные копии и временные файлы.

Проверка всей истории на строки, похожие на секреты:

```bash
git log -p --all | grep -nEi 'github_pat_|gh[pousr]_[A-Za-z0-9]{20,}|-----BEGIN [A-Z ]*PRIVATE KEY|api[_-]?key *[:=]|client_secret'
```

## Что уже сделано для защиты

* Токен не хранится в коде и не передаётся в адресах запросов; автотесты проверяют, что токена нет
  ни в `index.html`, ни в `assets/js`.
* Строгая Content Security Policy: скрипты только свои, без inline-кода; запросы наружу разрешены только
  к `api.github.com` и `raw.githubusercontent.com`, картинки — только свои.
* Весь пользовательский ввод экранируется, поэтому имя игрока или команды не может внедрить скрипт.
* Фото сжимается в браузере через canvas — EXIF (координаты съёмки, модель камеры) в файлы не попадает.
* Для Netlify и Cloudflare Pages в `_headers` заданы `X-Frame-Options: DENY`, `frame-ancestors 'none'`,
  `Permissions-Policy` и запрет лишних запросов.
* На GitHub Pages заголовки задать нельзя, поэтому от встраивания страницы в чужой iframe защищает
  `assets/js/frame-guard.js`: директива `frame-ancestors` действует только как заголовок, в `<meta>`
  браузеры её игнорируют.
* Локальный сервер `tools/serve.js` не выпускает за пределы каталога сайта и слушает только `127.0.0.1`.

## Ограничения статического сайта

* Панель нельзя закрыть настоящей авторизацией: любой пароль в исходниках виден. Реальная защита —
  только права GitHub-токена.
* GitHub Pages раздаёт весь репозиторий и всю его историю: скрыть файл или удалить данные задним числом
  нельзя. Если публиковать нужно только сам сайт, вынесите его файлы в каталог `docs/` или в ветку
  `gh-pages` (см. «Что публикуется» в README).
* Публичный репозиторий может быть скопирован кем угодно: удаление у вас не удаляет копии у других.

## Как сообщить о проблеме

Приватно: вкладка **Security** репозитория → **Report a vulnerability** — сообщение увидит только владелец.
Не создавайте публичный Issue с описанием уязвимости, пока она не закрыта.
